## 学んだこと

### レイテンシ

- Webアプリケーションのレイテンシは、リクエストを開始してからレスポンスを受け取るまでの遅延
- ネットワークの往復だけでなく、nginx、Node.js、DB、各種の待ち時間、レスポンス転送時間などを含む
- レイテンシは物理的な距離だけで決まらず、SQL、アプリケーション処理、キャッシュ、待ち行列、レスポンスサイズなども影響する
- 高速化しても、レスポンスの正しさを壊す変更は採用しない

### RTT、TTFB、総レスポンス時間

- RTT（Round Trip Time）は、通信相手との往復にかかる時間
- TTFB（Time To First Byte）は、リクエスト開始からレスポンスの最初の1バイトがクライアントへ届くまでの時間
- 総レスポンス時間は、レスポンス全体を受信し終わるまでの時間
- TTFBが長い場合は、最初の1バイトが返るまでのネットワーク、待機、Node.js、DBなどを疑う
- TTFBは短いが総レスポンス時間が長い場合は、レスポンスサイズ、転送速度、ストリーミング処理などを疑う

```text
クライアント
  │
  │ ① HTTPリクエストを送る
  ▼
ネットワーク
  │
  ▼
nginx
  │
  │ ② Node.jsへ転送する
  ▼
Node.js
  │
  │ ③ 必要に応じてSQLを発行する
  ▼
MySQL
  │
  │ ④ SQLの結果を返す
  ▼
Node.js
  │
  │ ⑤ HTTPレスポンスを作り始める
  ▼
nginx
  │
  │ ⑥ レスポンスをクライアントへ送る
  ▼
ネットワーク
  │
  │ ⑦ 最初の1バイトがクライアントへ到着
  │     ↑ ここまでがTTFB
  │
  │ ⑧ 残りのレスポンス本文がクライアントへ到着
  │     ↑ ここまでが総レスポンス時間
  ▼
クライアント
  │
  │ ⑨ JSON解析、JavaScript実行、HTML更新、画面描画
  ▼
表示完了
```

- TTFBの終点は、HTTPクライアントがレスポンスの最初の1バイトを読み取れるようになった時点
- レスポンス受信後のJSON解析、JavaScript実行、HTML更新、画面描画は通常TTFBに含まれない
- DNS、TCP接続、TLS接続などを計測に含めるかはツールや計測開始点によって異なる

### 順番待ち

- DBコネクションプールなどの資源がすべて使用中の場合、空くまで実質的なキューで待つ
- 設定された待ち時間を超えると、タイムアウトやエラーになる場合がある
- DB関連の時間も、コネクション取得待ちとSQL実行時間に分けて考える

### 平均、p95、p99

- 平均は、すべてのレイテンシの合計をリクエスト数で割ったもの
- p95は、約95%のリクエストがその時間以内に完了する境界
- p99は、約99%のリクエストがその時間以内に完了する境界
- p99は「一番重い種類のリクエスト」ではなく、観測したリクエストを速い順に並べたときの遅い側1%付近の境界
- 平均とp99は原因を特定する指標ではなく、全体や遅い側の変化を検知する指標
- p99は少数の遅いデータを見るため、複数回計測して再現性を確認する
- 平均やスコアにも揺らぎがあるため、可能なら同じ条件で複数回計測する

## 自分の言葉で説明

### レイテンシとは

クライアントがリクエストを飛ばしてから、サーバーを経由してレスポンスが返ってくるまでの時間。ネットワークだけでなく、プロキシサーバー、アプリケーション、DBなどの処理や待ち時間も含まれる。

### 平均とp99の違い

平均では全体的な性能の変化を見る。p99では、遅い側1%付近のリクエストがどの程度の時間で完了したかを見る。どちらも変化を検知した後は、ログから実際のリクエストを抽出して原因を調査する。

### p99が悪化した場合の調査手順

1. 同じ条件で複数回ベンチを実行し、悪化が再現するか確認する
2. アクセスログから時間がかかった実リクエストを抽出する
3. エンドポイントや発生条件ごとに分類する
4. Node.js、SQL、DBコネクション待ちなどへ処理時間を分解する
5. 原因候補を修正して再計測する

## 理解度チェックでの補足

- 平均が改善しても、特定のボトルネックが解消したとは限らない
- 平均の改善から断定できるのは、全体傾向としてレイテンシが改善したこと
- p99が悪化した場合は、遅い側で問題が起きた可能性を考え、実際の遅いリクエストを調査する
- `p99全体 = nginxのp99 + Node.jsのp99 + DBのp99`とはならない。各p99が同じリクエストを示すとは限らないため、実リクエスト単位で追跡する
