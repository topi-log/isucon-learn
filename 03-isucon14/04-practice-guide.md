# 3-4. 練習ガイド — 手を動かして素振りする

> **このドキュメントで学ぶこと**
> - ISUCON の練習環境の作り方（ISUCON14 / private-isu）
> - 効果的な素振りの進め方
> - 本番までのチェックリスト

読むだけでは ISUCON は速くなりません。「計測 → 改善 → 再計測」のループを**体に入れる**のが練習の目的です。

## 練習環境の選択肢

### 1. private-isu（最初の1回におすすめ）

[catatsuy/private-isu](https://github.com/catatsuy/private-isu) は練習用として最も定番の問題（画像SNS「Iscogram」）。書籍で丁寧に解説されており、独学の教材として最適です。

- **書籍『達人が教えるWebパフォーマンスチューニング 〜ISUCONから学ぶ高速化の実践』**（通称「ISUCON本」）がこの問題を題材に改善手順を一歩ずつ解説している。**ISUCON 初参加ならこの本を強く推奨**
- 改善内容が本ドキュメントの Part 2 とよく対応する（インデックス、N+1、画像の静的配信、キャッシュ…）
- AWS の AMI・Docker 環境が用意されている

### 2. ISUCON14 本番環境の再現

[isucon/isucon14](https://github.com/isucon/isucon14) に問題・ベンチマーカー・セットアップ手順が公開されています。README の手順に従って AWS 上に環境を構築できます（CloudFormation テンプレートが提供されるのが近年の通例）。

- Node.js 参考実装 (`webapp/nodejs`) に切り替えて、3-2・3-3 の内容を自分の手で再現する
- **注意**: EC2 の稼働費用がかかる。使わないときはインスタンス停止を忘れずに

### 3. その他

- 過去の ISUCON 問題も [isucon GitHub org](https://github.com/isucon) で公開されている（isucon13: ライブ配信サービス、isucon12: マルチテナントSaaS など）
- 有志の「ISUNARABE」などの練習用ポータルが利用できる場合もある（開催状況は都度確認）

## 素振りの進め方（1回 = 半日〜1日）

本番と同じ流れで時間を区切ってやるのが効果的です:

1. **セットアップ（〜1時間）**: ssh、git 管理、alp + pt-query-digest 導入、初回ベンチ、コード全体をざっと読む
   - この工程は本番でも毎回やる。**手順をスクリプト・メモ化して30分以内にできるようにする**のが素振りの大きな成果物
2. **計測して仮説を立てる**: alp と pt-query-digest の上位から改善候補リストを作る
3. **1つ改善 → ベンチ → 記録**: スコアの変化を必ずメモに残す（効かなかった改善も学び）
4. **終了後に答え合わせ**: 公式解説・他チームの参加記を読み、自分が見つけられなかったボトルネックを確認する。**ここが一番伸びる工程**

### 素振りで作っておく「秘伝のタレ」

回数をこなすと、毎回使うものが溜まっていきます。リポジトリにまとめておきましょう:

- 計測ツールのインストール・設定スクリプト（2-1 の bench-prepare.sh / analyze.sh）
- nginx / MySQL の定番設定ファイル（2-4, 2-6）
- デプロイスクリプト（ローカル編集 → rsync → ビルド → 再起動）
- 本番当日のチェックリスト（下記）

## 本番当日チェックリスト（雛形）

**序盤**
- [ ] マニュアルを全員で読む（スコア計算・許容遅延・禁止事項は必ず把握）
- [ ] git 初期化・全サーバーの構成確認（nproc, free, サービス一覧）
- [ ] 参考実装を Node.js に切り替え、ベンチが通ることを確認
- [ ] 計測ツール導入 → 初回計測結果を共有

**中盤**
- [ ] 改善は1つずつ、ベンチとセットで。スコアをスプレッドシート等に記録
- [ ] インデックスは初期化SQLに反映
- [ ] キャッシュ導入時は POST /initialize でのクリアを確認

**終盤（残り90分になったら）**
- [ ] 新規の大きな変更は凍結
- [ ] ログ類（access_log, slow_query_log, デバッグ出力）を無効化
- [ ] 全サービス enable 確認 → 全台再起動テスト → ベンチが通ることを確認

## 用語集

| 用語 | 意味 |
|------|------|
| private-isu | 練習用として最も定番のISUCON系問題（画像SNS）。書籍で改善手順が解説されている |
| ISUCON本 | 書籍『達人が教えるWebパフォーマンスチューニング』の通称。private-isuを題材にした実践解説書 |
| 素振り | 本番と同じ流れ（セットアップ→計測→改善→ベンチ）を練習として通しでやること |
| 感想戦 | 競技後に公式解説や他チームの記録と照らして答え合わせをすること。最も学びが大きい工程 |
| 参加記 | 参加者が書くふりかえりブログ。他チームの思考プロセスや構成が学べる |
| 秘伝のタレ | 毎回使う設定ファイル・スクリプト類をまとめた自分用リポジトリの俗称。回数を重ねて熟成させる |
| AMI | AWSの仮想マシンイメージ。練習用の環境がイメージとして配布されることがある |
| EC2 | AWSの仮想サーバーサービス。練習環境の構築先。**使わないときは停止しないと課金され続ける** |
| CloudFormation | AWSのインフラ一式をテンプレートから自動構築するサービス。近年のISUCON過去問環境はこれで立てるのが通例 |
| デプロイスクリプト | 「ローカル編集→サーバー転送→ビルド→再起動」を1コマンド化したスクリプト。サイクルタイム短縮の要 |
| チェックリスト | 当日にやること・確認事項の一覧。緊張していても抜け漏れを防ぐための道具 |
| ISUNARABE | 有志運営のISUCON練習用ポータルの名称。過去問ベンチをWebから実行できる（提供状況は要確認） |
