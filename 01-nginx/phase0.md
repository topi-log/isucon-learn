# phase0: 前提知識 — nginx を学ぶ前に

このフェーズでわかるようになること

- Web サーバーが何をする係なのか
- HTTP のリクエストとレスポンスのおおまかな中身
- ISUCON の構成図の中で nginx がどこにいるのか

nginx そのものはまだ出てきません。nginx を理解するための土台だけを作ります。

## Web サーバーとは何か

ブラウザで URL を開くと、裏では次のことが起きています。

1. ブラウザが「このページをください」というメッセージをサーバーに送る
2. サーバーがそれを受け取り、返すべき内容を用意する
3. サーバーが「はい、これです」と内容を送り返す
4. ブラウザが受け取った内容を画面に表示する

この「受け取って、返す」係のプログラムが Web サーバーです。
nginx（エンジンエックスと読みます）は世界でもっとも使われている Web サーバーの 1 つです。

## HTTP の超基本

ブラウザとサーバーのやりとりには HTTP という決まった形式を使います。
送る側のメッセージをリクエスト、返す側のメッセージをレスポンスと呼びます。

リクエストの例（ブラウザ → サーバー）:

```
GET /posts HTTP/1.1
Host: example.com
Cookie: session_id=abc123
```

- 1 行目の `GET` はメソッドと呼ばれ、何をしたいかを表します
  - GET: データがほしい（ページを見る）
  - POST: データを送る（投稿する、ログインする）
- `/posts` はパスです。サーバーの中のどれがほしいかを指します
- 2 行目以降はヘッダーです。「名前: 値」の形で付加情報を伝えます

レスポンスの例（サーバー → ブラウザ）:

```
HTTP/1.1 200 OK
Content-Type: text/html

<html>...ページの中身...</html>
```

- `200` はステータスコードです。処理の結果を数字で表します
  - 200 番台: 成功
  - 300 番台: リダイレクト（別の場所を見て、の案内）
  - 400 番台: クライアント側の間違い（404 = 見つからない、403 = 権限がない）
  - 500 番台: サーバー側のエラー（502 = 後ろのサーバーと話せない、504 = 待ちきれずタイムアウト）

ISUCON では 502 と 504 をよく見ることになります。意味は phase3 でわかります。

## IP アドレスとポート

サーバーの住所が IP アドレス、その中の窓口番号がポートです。
1 台のサーバーの中で複数のプログラムが通信を待てるように、番号で窓口を分けています。

よく使う番号は決まっています。

- 80: HTTP の標準ポート。ブラウザは `http://` のとき自動でここに行く
- 443: HTTPS（暗号化された HTTP）の標準ポート
- 8080: アプリケーションがよく使う番号。ISUCON でもアプリ（Node.js など）が
  8080 で待っている構成が定番です

つまり「外から来るリクエストは 80 番の nginx が受け、アプリは 8080 番で待つ」という
役割分担がこのあとの話の前提になります。

なお `127.0.0.1` という IP アドレスは「自分自身」を指す特別な住所です。
`127.0.0.1:8080` と書いたら「同じサーバー内の 8080 番で待っているプログラム」という意味です。

## 静的ファイルと動的レスポンス

サーバーが返す内容は 2 種類に分けられます。

- 静的ファイル: 誰が見ても同じ内容。CSS、JavaScript、画像など。
  ディスクにあるファイルをそのまま返すだけ
- 動的レスポンス: 人や状況によって変わる内容。タイムライン、検索結果など。
  アプリがデータベースに問い合わせて、その場で組み立てて返す

静的ファイルを返すのは単純作業なので、nginx はこれが非常に得意です。
一方、動的レスポンスはアプリにしか作れません。
「単純作業は nginx、頭を使う仕事はアプリ」という分担が ISUCON チューニングの基本になります。

## ISUCON の構成の中での nginx

ISUCON で渡されるサーバーは、だいたいこの形をしています。

```
ブラウザ（ベンチマーカー）
    |
    | HTTP リクエスト（80番ポート）
    v
+----------------------------------+
| サーバー                          |
|                                  |
|  nginx（80番で待つ）              |
|    |                             |
|    | 横流し（8080番へ）           |
|    v                             |
|  アプリ（Node.js など、8080番）   |
|    |                             |
|    | SQL                         |
|    v                             |
|  MySQL（データベース）            |
+----------------------------------+
```

nginx はいちばん手前の受付です。すべてのリクエストがまず nginx を通ります。
初期状態の nginx は、受け取ったものをほぼ全部アプリに横流ししているだけです。

この「横流し」役をリバースプロキシと呼びます。詳しくは phase3 でやりますが、
受付が手前にいるおかげで、次のことができるようになります。

- 静的ファイルは受付が自分で返して、アプリの仕事を減らす（phase5）
- すべてのリクエストの記録が受付に残るので、どこが遅いか計測できる（phase4）
- アプリを 2 台に増やしたとき、受付が仕事を振り分けられる（phase5）

## このフェーズのまとめ

- Web サーバーはリクエストを受けてレスポンスを返す係。nginx はその代表格
- HTTP はメソッド・パス・ヘッダー・ステータスコードでできている
- 80 番で nginx が受け、8080 番のアプリに横流しするのが ISUCON の定番構成
- 静的ファイルは nginx の得意分野。動的レスポンスはアプリの仕事
