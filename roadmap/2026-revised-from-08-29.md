# ISUCON 2026 学習ロードマップ再整理版

## 前提

- 再開日: 2026年8月29日（土）
- 本番: 2026年10月31日（土）
- 残り期間: 約9週間
- 完了済み: レイテンシ、RTT、TTFB、総レスポンス時間、平均、p95・p99の基礎
- 使用言語: Node.js / TypeScript
- 毎週木曜日: チーム定例
- 最初の実戦: 2026年9月22日（火）にチームで過去問を1問実施
- 当初確保できるとしていた時間: 平日1時間、土日各3時間以上

体調不良で実施できなかった項目を、そのまま後ろへ積み直さない。9月22日のチーム過去問を直近の目標とし、「基礎 → DB → Linux・nginx」の順で必要事項を学ぶ。10月の模擬本番2回と、本番用Runbookの完成を最優先にする。

## 今回の立て直し方針

1. 遅れを取り戻すための詰め込みをしない
2. 平日は理解と小さな確認、土日は環境上での実践に使う
3. すべてを学んでから過去問へ進まず、基礎と過去問を並行する
4. 一度に複数箇所を変更せず、「計測 → 仮説 → 一変更 → 再計測」を守る
5. 10月12日以降は、新しい知識より模擬本番と手順整備を優先する

9月22日までの学習順は固定する。

1. 基礎: HTTP、性能指標、Node.js / TypeScript、リクエスト処理の流れ
2. DB: SQL、インデックス、`EXPLAIN`、slow query log、N+1
3. Linux・nginx: プロセス、service、ポート、ログ、アクセスログ、基本的な計測

## 優先順位

### 必須

- HTTPリクエストがnginx、Node.js、MySQLを通る流れ
- Linuxでプロセス、ポート、service、ログ、CPU・メモリを確認する方法
- SQL、JOIN、インデックス、`EXPLAIN`、slow query log、N+1
- Node.jsの`async` / `await`、イベントループ、直列処理、DBコネクションプール
- nginxアクセスログから遅いエンドポイントを見つける方法
- ベースライン、一変更一ベンチ、変更記録、ロールバック、再起動確認
- 過去問演習1回以上、模擬本番2回
- 当日Runbook

### 余裕があれば

- nginxによる静的ファイル配信
- 安全なアプリ内キャッシュ
- レスポンスサイズ削減、重複計算削減
- MySQL、nginx、Node.jsの接続数とタイムアウトの調整
- CPUプロファイル、GC、イベントループ遅延の観測

### 今回は後回しにする

- 高度なLinuxカーネルチューニング
- MySQLオプティマイザ内部の深い理解
- worker_threadsやclusterを使った高度な並列化
- シャーディング、レプリケーション
- 大規模なアーキテクチャ変更
- 理由を説明できない設定値の一括コピー
